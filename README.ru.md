# Шрак VPN — демо Telegram-бота и Mini App

Красивое демо-приложение в тёмном неоновом стиле для показа клиентам. В нём есть каталог тарифов на 7/30/90 дней, демо-баланс, покупка подписки, личный кабинет, история операций, поддержка и закрытая панель владельца.

> **Важно:** это демонстрационный control-plane. Пополнение и покупка не списывают реальные деньги, а конфигурация `demo://...` не подключает настоящий VPN-сервер. Для запуска реального сервиса понадобится отдельный разрешённый VPS/managed VPN API и отдельная проверка платёжных правил.

## Быстрый локальный запуск

Нужен Node.js 20+.

```bash
npm test
npm run check
npm run build
npm start
```

Откройте [http://localhost:8787/?demo_user=100000001](http://localhost:8787/?demo_user=100000001).

В локальном режиме, когда `BOT_TOKEN` не задан, приложение использует только демонстрационный заголовок для тестового пользователя. В production этот режим должен быть выключен настройкой окружения с `BOT_TOKEN`.

## Как создать нового бота

1. В Telegram откройте `@BotFather`.
2. Отправьте `/newbot`.
3. Укажите отображаемое имя: `Шрак VPN`.
4. Укажите уникальный username, например `shrak_vpn_demo_bot` (username должен заканчиваться на `bot`).
5. Сохраните токен локально. **Не отправляйте токен в чат и не коммитьте его в Git.**
6. После публикации укажите Web App URL через BotFather или используйте кнопку, которую отправляет webhook.
7. Аватарку из `public/branding/avatar.svg` можно открыть в браузере и сохранить как изображение для загрузки через `/setuserpic`.

## Единственный администратор

Админ-панель доступна только пользователю, чей числовой Telegram ID совпадает с `ADMIN_TELEGRAM_ID` на сервере. Клиентам этот ID не показывается и не передаётся в URL.

Получите свой числовой ID самостоятельно через проверенный Telegram-инструмент, затем задайте в секретах деплоя:

```env
ADMIN_TELEGRAM_ID=123456789
```

Если переменная не задана, все `/api/admin/*` маршруты закрыты.

## Переменные окружения

Скопируйте `.env.example` в `.env` только локально. Внешние секреты задаются в панели хостинга:

- `PORT` — порт HTTP-сервера;
- `PUBLIC_APP_URL` — публичный HTTPS URL приложения;
- `BOT_TOKEN` — секрет от @BotFather;
- `ADMIN_TELEGRAM_ID` — ваш единственный числовой Telegram ID;
- `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` — зарезервированы для подключения Supabase persistence.

## Публикация

Для демо можно использовать Render Web Service с командой запуска `npm start`, а Supabase — для постоянной базы после замены in-memory store на Supabase API. На бесплатном Render возможен cold start, поэтому это не production SLA.

Порядок:

1. Создайте GitHub-репозиторий и загрузите проект.
2. Создайте проект Supabase и примените `supabase/migrations/001_init.sql`.
3. Создайте Render Web Service из репозитория.
4. Добавьте environment variables через защищённую панель Render.
5. Укажите `PUBLIC_APP_URL` с HTTPS URL Render.
6. Проверьте `/start` и кнопку открытия Mini App.
7. Никому не передавайте `BOT_TOKEN` и `SUPABASE_SERVICE_ROLE_KEY`.

## Структура

- `apps/api/server.mjs` — HTTP API, webhook и серверная проверка доступа;
- `apps/api/telegram.mjs` — HMAC-валидация Telegram Mini App `initData`;
- `apps/api/store.mjs` — демонстрационная бизнес-логика баланса/покупок;
- `apps/web/` — Mini App, кабинет и owner-only admin UI;
- `public/branding/` — аватарка и favicon;
- `supabase/migrations/` — схема постоянного хранения для следующего этапа;
- `tests/` — проверки баланса, покупки и идемпотентности.
